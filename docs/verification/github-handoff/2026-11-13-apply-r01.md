## 離線重播

### 方法

- 每個案例只提供 Fixture 與模擬回覆。以腳本從來源檔產生去除答案的副本：移除「預期
  呼叫」「禁止」「判定」三行與案例標題文字，契約副本截去附錄 A，Skill 副本不含案例檔。
- 四個獨立子 Session 分批重播：C-01–C-18、GI-01–GI-14、GP-01–GP-11、GP-12–GP-18。
  每個 Session 讀取契約與相關 Skill，寫出會提出的呼叫與回報；沒有執行任何 `git`、`gh`、
  `ssh` 或腳本。
- 比對由實作 Session（Claude Fable 5.2）逐案對照來源檔的預期呼叫、禁止與判定完成。
  **沒有人類參與比對。**

## 已知限制

- 重播的比對者是撰寫契約與 Skill 的同一個實作 Session，不是人類，也不是獨立 Reviewer。
- 同一批次的案例在同一個子 Session 內依序回答，彼此並非完全獨立；部分模擬回覆本身
  透露了呼叫順序。
- 重播是決策驗收：沒有真實的 staging、commit、push、帳號查驗或 GitHub 寫入。
- 三種工具中只有 Claude Code 有 runtime 證據（安裝後兩個 Skill 出現在本 Session 的可用
  Skill 清單）。其他工具只驗證了安裝位置與文件鏈：`.agents/skills/`、`.agents/rules/`，
  以及 AGENTS.md → `docs/agent-protocol.md` → `docs/github-handoff.md` → 腳本。
- HTTPS 的 `gh auth git-credential` 路徑只有 stub 測試；「helper 與 `gh api` 使用同一個
  token」來自設計階段的原始碼查閱，尚未以真實帳號實測。
- 契約腳註的外部來源沿用設計階段的查閱紀錄，本輪沒有重新查閱。
- 本專案的 `AGENTS.md` 還沒有 `## GitHub handoff identity` 區塊；預期身分須由使用者宣告。
- tasks 5.1 需要已登入的 `gh`、明確授權的測試 repository 與可信身分政策，三者目前都
  不具備，因此未執行。
